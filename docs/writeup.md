# VOTE-GUARD 360: write-up

**Hackathon:** Every Vote, Every Voice (KTech Fest 3.0) · **Team 15**
**Live demo:** https://voteguard-360.vercel.app · **Code:** https://github.com/ktechfest2/TEAM-15-3.0

## The problem

The count that matters is written on one sheet at each polling unit. Photos of those sheets travel by messaging app with no proof of when they were taken or whether they were edited, two photos can show different numbers with no way to say why, and many people cannot read a dense table or have a reliable connection. See [problem-brief.md](problem-brief.md).

## The solution

VOTE-GUARD 360 is an **independent evidence layer** for result sheets. It is not an INEC system, it does not collate or declare results, and it never says "fraud", "correct" or "winner".

1. **Capture** on a phone. The fingerprint (SHA-256) is taken on the device, and photos queue offline until a signal returns.
2. **Keep the original** in write-once storage. The server re-hashes the stored file and flags any mismatch.
3. **Read and check**: figures are read from the photo, shown with a confidence flag, and the observer confirms or fixes them. Five arithmetic rules are checked.
4. **Compare independent photos.** Independent means a different person and a different file. The differing figure is highlighted without saying which is right.
5. **Human review**: a reviewer sees photos side by side and records a decision with a public note.
6. **Neutral public status** (five states) and a **collation tracker** that sets agreed-unit totals beside a synthetic published ward figure only when every unit is counted.
7. **Tamper-evident history**: each step is an audit event linked to the one before; anyone can check the whole chain.
8. **Access layer**: "Listen to this result sheet", an accessibility mode, and easy-read status text in English and Nigerian Pidgin.

## What is real and what is not

- **Real and running:** capture with on-device hashing, offline queue and service worker, signed uploads, write-once storage, server re-hash, arithmetic checks, comparison, status rules, reviewer decisions, hash-chained audit log enforced by the database, row-level security, public evidence pages, dashboard, Listen, accessibility settings. Over 200 automated tests, plus five database tests run against the live project.
- **Stubbed:** reading figures from photos. The three demo sheets (and a second photo of one of them) are served from stored results keyed by file fingerprint; any other image is marked unreadable and sent to a person, never guessed. The call to a vision model sits behind an adapter and is not connected in this build.
- **Synthetic:** every polling unit, sheet, figure and the "published" ward total. All are labelled DEMO.
- **Needs checking by a speaker:** the Pidgin text. Spoken audio is English only because phones have no Pidgin voice, so Pidgin shows text rather than faking audio.

## AI usage

- **Coding assistant:** built with Claude Code (Anthropic, Claude Sonnet 5.5), declared as the rules require. Logic was written test-first.
- **In the product:** a vision-model reader is designed in but stubbed (above). Narration is generated by deterministic code from verified fields and the status; no language model writes what users hear.

## Tools and libraries

## Honest limits

A fingerprint shows the photo has not changed since capture; it does not prove the document was genuine. Machine reading can be wrong. A single observer cannot make a unit "agree"; at least two independent people are needed. Real IReV/INEC records are not imported; an adapter boundary is left for that.

## Roadmap

Live vision reader with human fallback; near-duplicate image detection; SMS/USSD and IVR capture and listening for people without smartphones; Hausa, Yorùbá and Igbo text; importing official public records as another source for comparison.
