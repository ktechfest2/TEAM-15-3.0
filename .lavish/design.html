5Modules and the tests we write first

The heart of the product is plain functions with no network or database, so lane B can write failing tests before anything else exists.

Module (packages/evidence)First failing tests
sha256(file)Known vectors; same bytes give same hash; one flipped byte changes it; browser and server agree
validateArithmetic(fields)Parties sum to valid; valid + rejected = cast; cast ≤ accredited ≤ registered; negatives, blanks and missing fields flagged
compareSubmissions(a, b)Identical values agree; one differing field is reported by name; the same file hash from two senders is not independent
statusFor(unit)Every transition in diagram 3c, and nothing outside it
chainAuditEvent / verifyChainEach event stores the previous hash; changing or removing any event makes verification fail
narrate(unit, language)Reads only verified fields and the status; never uses "correct", "fraud" or "winner"; numbers spoken in full

Open design points, with my default

Who counts as "independent"? Two different signed-in observers. Can the public submit? Not in the prototype: observers only, to keep abuse out. Where do the 12 sample units live? A seed script, all stamped DEMO.
