# VOTE-GUARD 360

> Every vote leaves evidence. Every result deserves verification.

Built for the **"Every Vote, Every Voice"** hackathon (KTech Fest 3.0, Team 15).

VOTE-GUARD 360 is an **independent evidence layer** for polling-unit result sheets. An observer photographs a sheet; the app fingerprints it on the phone, stores the original, reads the figures, checks the arithmetic, compares independent photos and shows a neutral public status with a tamper-evident history. A "Listen" feature, an accessibility mode and easy-read text (English and Nigerian Pidgin) make it usable by people who cannot easily read the sheet or the screen.

**It is not an INEC system.** It does not collate or declare results, and a mismatch means "a person should take a look", never "fraud".

## Important limitations

- **All data is synthetic demo data**, clearly labelled DEMO in the app and in the sample sheets. No real election data is used.
- A fingerprint proves a file has not changed since it was captured. It does **not** prove the document was genuine.
- Reading figures is machine-assisted and can misread; low-confidence values are flagged for human review. In this build the reader is stubbed (see below).
- Pidgin text needs a native-speaker check; browser voices for Hausa, Yorùbá and Igbo are limited, so those show text only.
- Real INEC/IReV records are not imported (an adapter interface is left for that).

## Setup

```bash
npm install
npm test            # all packages: evidence, extraction, web (200+ tests)
npm run typecheck
npm run dev -w @voteguard/web      # needs .env.local, see below
```

Environment variables go in `.env.local` at the repo root (never committed); see `.env.example`. The browser needs `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`; the server routes also need `SUPABASE_SERVICE_ROLE_KEY`. `EXTRACTION_MODE=cached` serves stored results for the demo sheets.

**Database:** run `database/schema.sql` then `database/seed.sql` in the Supabase SQL editor, then each file in `database/tests/pieces/` (each ends by raising `PASS n`, which is success). See `database/tests/README.md`.

**Demo story:** `NODE_PATH=$PWD/node_modules node scripts/demo-scenario.cjs` plants four units through the real API. It needs demo logins, which are created in the project and shared with judges separately, never committed.

## AI usage declaration

- **AI coding assistant:** this project was built with **Claude Code** (Anthropic, Claude Sonnet 5.5). The rules require declaring this.
- **AI in the product:** reading figures from photos is designed to use Claude vision behind an adapter, but **in this build that call is a stub**: the demo sheets are served from stored results keyed by file fingerprint, and any other image is flagged unreadable for a person. Narration text is generated by deterministic code from verified fields, not by a language model.
